# Практическая работа № 5 — Основы TypeScript. Типизация данных и функций

Практическая работа посвящена изучению основ TypeScript и использованию статической типизации при разработке приложений. В ходе выполнения создана типизированная модель интернет-магазина: описаны товары и пользователи, реализованы функции поиска и фильтрации, а также структуры данных для взаимодействия frontend и backend.

Проект использует строгий режим TypeScript (`strict`), благодаря которому компилятор проверяет соответствие данных заданным типам.

## 📚 Выполненные задания

### Задание 1. Настройка проекта

Создан проект `practical-work-5` с использованием Node.js и npm.

Установлен TypeScript в качестве зависимости для разработки. Создан файл конфигурации `tsconfig.json`, настроены параметры компилятора и включён строгий режим проверки типов.

Исходный код размещён в папке `src`, а скомпилированные JavaScript-файлы сохраняются в `dist`.

### Задание 2. Базовые типы

Созданы переменные с явным указанием типов:
- `shopName: string` — название магазина;
- `year: number` — год;
- `isOnline: boolean` — состояние интернет-магазина.

Дополнительно создана переменная `description: string | null`, которая может содержать строку или значение `null`.

Объединение типов позволяет использовать несколько допустимых типов данных для одной переменной.

### Задание 3. Создание типа товара

Создан пользовательский тип `Product`, описывающий структуру товара.

Он включает следующие свойства:
- `id` — идентификатор;
- `name` — название;
- `price` — цена;
- `category` — категория;
- `inStock` — наличие товара.

Созданы три объекта товаров и объединены в массив `products` типа `Product[]`.

### Задание 4. Необязательные свойства

В тип `Product` добавлено необязательное свойство `description?: string`.

Для одного товара задано описание, остальные товары созданы без этого свойства.

При выводе информации используется проверка наличия описания. Если оно отсутствует, программа выводит соответствующее сообщение.

Необязательное свойство отличается от обязательного тем, что объект может не содержать его вовсе.

### Задание 5. Literal и Union-типы

Создан тип `ProductCategory`, который допускает только три значения:
- `computers`;
- `phones`;
- `accessories`.

Поле `category` в типе `Product` использует созданный тип.

Это ограничивает возможные значения категории и позволяет TypeScript обнаруживать недопустимые варианты, например `food`.

### Задание 6. Функция вывода товара

Реализована функция `printProduct(product: Product): void`.

Она принимает объект типа `Product` и выводит его основные характеристики:
- название;
- цену;
- категорию;
- наличие;
- описание, если оно задано.

Функция вызывается для всех элементов массива `products` с помощью `forEach()`.

### Задание 7. Функция поиска товара

Создана функция `findProductById(products, id)`, которая выполняет поиск товара по идентификатору с помощью метода `find()`.

Возвращаемый тип функции — `Product | undefined`.

Значение `undefined` возвращается в том случае, если товар с указанным идентификатором не найден.

### Задание 8. Фильтрация товаров

Реализована функция `getAvailableProducts(products): Product[]`.

С помощью метода `filter()` она формирует новый массив, содержащий только товары, у которых свойство `inStock` равно `true`.

### Задание 9. Фильтрация по цене

Создана функция `getProductsByMaxPrice(products, maxPrice): Product[]`.

Функция возвращает товары, стоимость которых не превышает заданную максимальную цену.

Для проверки использовано ограничение в 50 000 рублей.

### Задание 10. Interface

Создан тип `UserRole` с тремя возможными ролями:
- `admin`;
- `manager`;
- `customer`.

Разработан интерфейс `User`, определяющий структуру пользователя магазина: идентификатор, имя, электронную почту и роль.

Созданы три пользователя с разными ролями и объединены в массив `users`.

### Задание 11. Расширение интерфейса

Создан интерфейс `Admin`, расширяющий интерфейс `User` с помощью `extends`.

Администратор наследует все свойства пользователя и дополнительно содержит массив `permissions`, в котором перечислены доступные действия: создание, редактирование и удаление.

### Задание 12. DTO

Создан интерфейс `CreateProductDto`, описывающий структуру данных для передачи информации о новом товаре от frontend к backend.

Интерфейс содержит:
- `name` — название;
- `price` — цена;
- `category` — категория.

Свойства `id` и `inStock` отсутствуют, поскольку предполагается, что они формируются на стороне backend.

Создан объект `newProduct`, соответствующий интерфейсу DTO.

## 🗂️ Структура проекта

```text
practical-work-5/
├── src/
│   └── index.ts          # Исходный код TypeScript
├── dist/
│   └── index.js          # Скомпилированный JavaScript
├── node_modules/         # Установленные зависимости
├── package.json          # Описание проекта и зависимости
├── package-lock.json     # Зафиксированные версии зависимостей
├── tsconfig.json         # Конфигурация TypeScript
└── README.md             # Описание практической работы
```

Папка `node_modules` создаётся автоматически при установке зависимостей. Она не включается в систему контроля версий.

Папка `dist` содержит результат компиляции исходного TypeScript-кода.

## 🚀 Запуск

Для работы с проектом необходимы установленные Node.js и npm.

1. Откройте терминал.
2. Перейдите в папку проекта:

```bash
cd practical-work-5
```

3. Установите зависимости:

```bash
npm install
```

4. Проверьте TypeScript-код без создания JavaScript-файлов:

```bash
npx tsc --noEmit
```

5. Выполните компиляцию:

```bash
npx tsc
```

6. Запустите программу:

```bash
node dist/index.js
```

После выполнения программы в терминале отобразятся результаты всех двенадцати заданий.

## 🛠️ Используемые технологии

- **TypeScript** — язык программирования со статической типизацией.
- **JavaScript** — язык, в который компилируется исходный TypeScript-код.
- **Node.js** — среда выполнения JavaScript.
- **npm** — менеджер пакетов для установки и управления зависимостями.
- **HTML5 / CSS3** — не используются в данной работе, поскольку задания посвящены типизации и логике приложения.
