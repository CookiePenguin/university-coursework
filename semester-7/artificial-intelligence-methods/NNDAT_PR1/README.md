# Практическое задание № 1: Основы матричной алгебры и классы в Python

**Дисциплина:** Методы искусственного интеллекта  
**Тема:** Реализация матричных операций «с нуля» и сравнение с NumPy

## 1. Цель работы

Изучить основы матричной алгебры, научиться реализовывать матричные операции на чистом Python без использования специализированных библиотек, а также освоить объектно-ориентированный подход (классы) и сравнить производительность собственных реализаций с библиотекой NumPy.

**Задачи:**
1. Реализовать функции для сложения матриц, умножения на число, поэлементного умножения, скалярного произведения и транспонирования.
2. Создать класс, инкапсулирующий эти операции.
3. Сгенерировать матрицы размером 9×11, выполнить операции собственными функциями и средствами NumPy, замерить время выполнения и проверить корректность результатов.

## 2. Реализация

Все операции реализованы с использованием вложенных списков (`list[list[int]]`) и циклов.  
Класс `MatrixOps` предоставляет статические методы для удобного вызова.  
Весь исходный код находится в файле `main.py`.

## 3. Результаты

### 3.1. Проверка на примерах из методички

Все операции дают результаты, полностью совпадающие с ожидаемыми значениями из задания:

- **Сложение:** `[[5, 3], [10, -2], [-4, 10]]`
- **Умножение на число (3):** `[[6, -9, 3], [15, 0, 12]]`
- **Поэлементное умножение:** `[[6, -4], [21, 0], [-5, 24]]`
- **Скалярное произведение:** `[[6, 2, 7], [19, 8, 13]]`
- **Транспонирование:** `[[2, 5, 4], [1, 3, 7]]`

### 3.2. Сравнение с NumPy (матрицы 9×11)

Все результаты собственных функций совпали с результатами NumPy (проверено через `np.array_equal`).

| Операция | Время (свои), с | Время (NumPy), с | Результаты совпадают |
|----------|------------------|------------------|----------------------|
| Сложение | 0.000058 | 0.000223 | Да |
| Умножение на число | 0.000025 | 0.000060 | Да |
| Поэлементное умножение | 0.000025 | 0.000009 | Да |
| Скалярное произведение | 0.000125 | 0.000054 | Да |
| Транспонирование | 0.000055 | 0.000005 | Да |

### 3.3. Выводы

- Собственные реализации на чистом Python работают **корректно**, что подтверждено проверкой на эталонных примерах и сравнением с результатами NumPy.
- На малых матрицах (9×11) чистый Python в некоторых операциях (сложение, умножение на число) оказался **быстрее** NumPy. Это связано с накладными расходами NumPy на создание объектов `ndarray`, приведение типов и векторизацию. На малых объёмах данных эти накладные расходы превышают выигрыш от оптимизированных C-циклов.
- Однако на операциях с большим количеством арифметических действий (поэлементное умножение, скалярное произведение, транспонирование) NumPy ожидаемо быстрее, так как использует векторизованные вычисления на C.
- С ростом размера матриц преимущество NumPy будет становиться всё более значительным, поскольку накладные расходы остаются фиксированными, а объём вычислений растёт квадратично (или кубично для скалярного произведения).
- Класс `MatrixOps` позволяет удобно группировать операции, скрывать детали реализации и при необходимости легко расширять функциональность.
